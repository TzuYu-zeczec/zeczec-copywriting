# 募資前測問卷產出工具

## 概述

本 skill 用於從產品資料出發，產出完整的募資前測問卷。支援兩種主流問卷平台：

| 平台 | 體驗特性 | 圖片規格 | 適用場景 |
|------|---------|---------|---------|
| **SurveyCake** | 長頁滾動，題目全部在同一頁 | 1200×600 / 800×600 / 1080×1080 | 功能複雜、需要大量說明的產品 |
| **Typeform** | 一次一張圖卡，逐步沉浸式體驗 | 1080×1520（直式） | 品牌感強、需要帶著填答者走的產品 |

最終交付物：
1. **問卷文案**：含每張圖的文案、題目內容、圖片規格標註
2. **配圖規格說明**：所有問卷配圖的視覺規格描述，可交給設計師製作

核心理念：問卷不只是問問題，而是一場迷你版的銷售頁體驗。

> **⚠️ 平台限制：本文案系統僅適用於嘖嘖。**
> 所有問卷文案中提及募資平台的位置（Opening、價格方案、好禮誘因、Email 引導等），一律寫「嘖嘖」。
> 不得出現任何其他募資平台名稱。

## 依賴的其他 skill

- **persona-matrix**（可選）：如果已有受眾輪廓矩陣，痛點題與情境選項會更精準
- **copy-style-guide**（可選）：文案語感參考

## 參考資料（已自動載入）

以下參考文件已自動載入至系統提示中，請直接套用：
- **問卷製作方法論**：完整的判斷邏輯、題型規則
- **SurveyCake 互動式問卷 HTML 格式規範**：互動式 HTML 問卷的元件結構、設計系統（適用 SurveyCake 路徑）
- **Typeform 募資問卷格式規範**：Typeform 專屬的圖片版面解剖、銜接按鈕範例、問題題型規範（適用 Typeform 路徑）

# ═══ Part A：SurveyCake 路徑 ════════════════════════════════

## A 概述

SurveyCake 問卷為長頁滾動式，所有題目與圖片都在同一頁，填完才送出。
星級題打主力賣點，多選題補完次要特色並收集偏好數據。

---

### A-Step 1｜產品資料拆解

**輸入**：使用者提供的產品資訊（文字、PDF、xlsx、圖片皆可）

**執行內容**：
1. 提取以下資訊並整理成表格：

| 項目 | 說明 |
|------|------|
| USP | 市場上只有這個產品做得到的事 |
| KSP × 3-5 個 | 各自值得獨立講的主力賣點 |
| 背景議題／核心痛點 × 4-6 個 | 消費者目前遇到的困擾 |
| 最佳使用情境 × 2-3 個 | 最能打動人的使用場景 |
| 關鍵規格 | 消費者能感受到差異的技術規格 |
| 其他規格／貼心特色 | 有加分但不是主力的特色 |
| 競品資訊 | 競品做不到什麼、價格帶 |

2. 如果有 persona-matrix 的受眾矩陣，一併讀取，用於後續痛點與情境設計。

**確認點**：向使用者確認拆解結果是否正確，有無遺漏。

---

### A-Step 2｜功能分類分群

**執行內容**：

將 A-Step 1 拆解出來的特色，依以下維度歸組：

- **依情境**：在某某情境下，這些功能好用
- **依受眾**：針對某某人，這些功能最相關
- **依特色類別**：同類型功能放一起（安全性、便利性、智慧連動…）

**分類原則**：
- 每組要有 4 個以上選項，才值得做成一題多選
- KSP 不放在多選裡，獨立做星級題
- 次要但加在一起有分量的特色 → 歸類成「貼心設計」多選

**產出格式**：列出分群結果，標註每組預計的題型（星級／多選）

**確認點**：向使用者確認分群邏輯。

---

### A-Step 3｜題型分配與問卷架構

**執行內容**：

根據 A-Step 2 的分群結果，決定每一題的題型與順序。

#### 題型判斷邏輯

| 判斷條件 | 使用題型 |
|----------|----------|
| 主力賣點，有獨立拉篇幅的價值 | ⭐ 星級題 |
| 完整可分類的特色，4 個以上，非主力 | 多選題（歸類貼心特色） |
| 同一功能的多種使用情境 | 多選題（選情境） |
| 選顏色、選配件、選方案 | 多選題（選規格） |
| 需要市場教育，創造需求 | 多選題（問痛點，放最前面） |
| 整體購買意願 | ⭐ 星級題（固定放最後） |

#### 星級題與多選題的搭配

星級題跟多選題可以講同一件事。實務做法：星級題講完大賣點 → 接續的多選題讓使用者選該賣點的使用情境。

#### 標準問卷結構

```
一、主標題／主視覺圖                         [1200x600]
二、Opening 開場（100-150字）                [800x600 特色簡介圖]
    ＋好禮誘因區塊                           [800x600 誘因圖]
三、（若需市場教育）痛點多選題
四、⭐ 星級題 1 — 主力賣點 #1                [800x600]
    （可接多選題：該賣點的使用情境）          [1080x1080 × N 選項圖]
五、⭐ 星級題 2 — 主力賣點 #2                [800x600]
    （可接多選題：該賣點的使用情境）          [1080x1080 × N 選項圖]
六、⭐ 星級題 3 — 主力賣點 #3                [800x600]
    （可接多選題：該賣點的使用情境）          [1080x1080 × N 選項圖]
七、多選題 — 貼心特色／安全設計              [1080x1080 × N 選項圖]
八、⭐ 購買意願星級題（含價格方案）           [800x600 價格圖]
九、Email
十、手機
十一、開放題 — 請留下建議
十二、送出 → 跳轉 LINE 參加抽獎             [800x600 跳轉圖]
```

**題數控制**：總題數 15 題以內（含填寫題與開放題）。
**多選題限選**：全部設定最多選 2-3 個，避免全勾。

**產出格式**：問卷架構表，含題號、題型、內容摘要、圖片規格

**確認點**：向使用者確認架構，有無要增刪或調換順序。

---

### A-Step 4｜問卷文案撰寫

**確認完架構後，開始撰寫完整問卷文案。**

#### Opening 寫法

- 100-150 字，寫產品概述
- 列出 X 大產品特點，或凸顯銷售成績
- 搭配格狀特色簡介圖（6 宮格）
- 標配好禮誘因區塊：
  ```
  即將登上嘖嘖募資
  2 分鐘填寫問卷 享 3 大好禮
  $OOO 元專屬折扣碼｜開賣首發通知｜好禮抽獎機會
  ```

#### 星級題文案架構

每一題星級題包含：

1. **主標語**：一句話，口語化，傳遞感受而非規格
2. **副標語**：補充規格或技術名詞，用「｜」分隔
3. **配圖位置**：標註圖片建議內容與尺寸（800x600）
4. **敘述文字**：2-4 行，每行講一個利益點，從消費者角度出發
5. **星級量表說明**：例如「七顆星＝非常想用；一顆星＝非常無感」

#### 多選題文案架構

每一題多選題包含：

1. **題目**：一句話問清楚在選什麼
2. **副標**：標示限選數量
3. **選項**：選項名稱 ＋ 一句話說明好處
4. **選項配圖**：每個選項標註圖片建議內容（1080x1080）

#### 痛點多選題寫法（若有）

- 放在問卷最前面
- 題目格式：「你是否遇過以下困擾？」
- 選項要涵蓋產品能解決的核心痛點
- 後續星級題會逐一回應這些痛點

#### 購買意願星級題

- 放在最後（Email 之前）
- 含價格資訊或募資方案
- 含加碼優惠（贈品、免運、分期等）
- 星級量表：「七顆星＝非常想買；一顆星＝非常不想買」

#### 收集資料區

- Email：說明會寄送折扣碼與首發通知
- 手機：說明會以簡訊同步通知（標註僅限本次活動）
- 開放題：歡迎留下產品建議、功能期待、價格想法

#### 送出跳轉

- 感謝語
- 引導跳轉 LINE 官方帳號
- 參加好禮抽獎 + 接收開賣通知

#### 輸出格式

- 每題之間用分隔線隔開
- 題號用藍色標題標示（例：Q1 多選題｜痛點）
- 題型用色標標籤標示（星級題藍色、多選題橘色）
- 圖片位置用虛線框 placeholder 標示，含尺寸與建議內容
- 文末附錄：圖片製作清單表格（含編號、位置、內容、尺寸、備註）

---

### A-Step 5｜互動式問卷 HTML 設計稿

**問卷文案完成後，產出互動式 HTML 問卷設計稿。**

> 完整格式規範（SurveyCake 互動式問卷 HTML 格式規範）已自動載入，請直接套用。

#### 輸出格式

以「全螢幕逐題滑動」的互動式 HTML 呈現整份問卷，單一 .html 檔案（CSS + JS 全部內嵌）。

**核心互動**：
- 每題一個全螢幕 slide，淡入淡出 + 垂直位移動畫切換
- 固定頂部進度條（4px 漸層色條）
- 固定右側導航圓點（可點擊跳轉）
- 鍵盤操作（Enter / ↑↓）+ 手機觸控滑動

#### 品牌色系統

用 CSS Variables 管理，每份問卷只需替換三個色值：

```css
--brand: #品牌主色;
--brand-dark: #品牌深色;
--brand-light: #品牌淺色;
```

#### 六種 Slide 元件

| 元件 | class | 用於 |
|------|-------|------|
| Opening 封面 | `.opening-*` + `.feature-grid` + `.incentive` | 品牌名、產品名、主標語、6 宮格特色、好禮誘因 |
| 星級題 | `.sp-card` + `.star-container` | 賣點卡片（badge + 主標 + 說明 + 規格數據）+ 7 星評分 |
| 多選題 | `.choice-grid` + `.choice-item` | 打勾選項列表（主文字 + 副文字）+ 限選提示 |
| 購買意願 | `.price-card` + `.star-container` | 價格卡片（原價刪除線、早鳥價、加碼優惠）+ 7 星評分 |
| 輸入題 | `.input-field` | Email / 手機 / 開放題（textarea） |
| 感謝頁 | `.thankyou-icon` + `.line-btn` | 感謝文字 + LINE 官帳按鈕 |

#### 產出步驟

1. 從範例模板複製 CSS 設計系統與 JS 互動邏輯
2. 替換 `--brand` / `--brand-dark` / `--brand-light` 為該產品品牌色
3. 依問卷架構逐題建立 slide HTML
4. 修改 JS 中的 `totalSlides` 數值
5. 瀏覽器全螢幕預覽確認體驗流暢

### A 自我檢查清單

完成問卷文案與配圖後，逐項確認：

1. ☐ 總題數是否在 15 題以內
2. ☐ 痛點多選題是否放在星級題之前（先激發需求再回應）
3. ☐ 星級題是否只用於主力賣點（不值得獨立講的不要用星級）
4. ☐ 多選題是否都設了限選數量（最多 2-3 個）
5. ☐ 星級題與多選題的搭配是否合理（大賣點星級 → 接情境多選）
6. ☐ Opening 是否在 100-150 字以內
7. ☐ 好禮誘因是否完整（折扣碼＋首發通知＋抽獎）
8. ☐ 購買意願星級題是否含價格資訊
9. ☐ Email / 手機 / 開放題是否都有
10. ☐ 送出後是否有跳轉 LINE 的引導
11. ☐ 文末是否附圖片製作清單表格

**互動式 HTML 檢查**
12. ☐ HTML 是否能在瀏覽器中完整操作（逐題切換、星級點擊、多選限選）
13. ☐ 品牌色是否已替換（--brand / --brand-dark / --brand-light）
14. ☐ JS totalSlides 數值是否正確
15. ☐ 每種 slide 元件是否對應正確（Opening / sp-card / choice-grid / price-card / input / 感謝頁）
16. ☐ 進度條、導航圓點、鍵盤操作是否正常運作

# ═══ Part B：Typeform 路徑 ════════════════════════════════

## B 概述

Typeform 問卷由「圖片卡片」和「問題題組」交錯排列。每張圖片卡片尺寸為 **1080 × 1520px**（直式），一次只顯示一張，沉浸感強。圖片卡片之間插入問題題組，段落與段落間有銜接文字按鈕引導往下滑。

**整體流程固定為：**

```
封面圖（Opening）
  ↓ [銜接按鈕]
Q1 — 痛點確認（多選題）
  ↓ [銜接按鈕]
特色圖 ① 核心差異化賣點（最強、最獨特）
  ↓ [銜接按鈕]
特色圖 ② 第二賣點
  ↓ [銜接按鈕]
特色圖 ③ 第三賣點
  ↓ [銜接按鈕]
特色圖 ④ ~ ⑥（依產品複雜度調整，標準 5-6 張）
  ↓ [銜接按鈕]
Q2 — 使用情境 / 偏好（單選題）
  ↓ [銜接按鈕]
Q3 — 購買意願星級題（1~7 顆星，附早鳥價格圖）
  ↓ [銜接按鈕]
Q4 — Email（必填）
  ↓ [銜接按鈕]
Q5 — 手機號碼（選填）
  ↓ [銜接按鈕]
Q6 — 開放意見（選填）
  ↓
感謝頁（結束 / 跳轉）
```

**總圖片數參考：**

| 問卷長度 | 圖片張數 | 問題數 | 適用 |
|---------|---------|-------|------|
| 精簡版 | 3–4 張 | 3–4 題 | 粉絲已熟悉產品 |
| 標準版 | 5–6 張 | 5–6 題 | 一般前測問卷 |
| 完整版 | 7–8 張 | 6–8 題 | 功能複雜的產品 |

---

### B-Step 1｜產品資料拆解

與 SurveyCake 路徑的 A-Step 1 相同，提取以下資訊：

| 項目 | 說明 |
|------|------|
| USP | 市場上只有這個產品做得到的事 |
| KSP × 3-6 個 | 各自值得獨立做一張圖的主力賣點 |
| 核心痛點 × 4-6 個 | 消費者目前遇到的困擾 |
| 最佳使用情境 × 3-5 個 | 最能打動人的使用場景 |
| 競品資訊 | 競品做不到什麼（用於 Before/After 對比） |

**確認點**：向使用者確認拆解結果是否正確，有無遺漏。

---

### B-Step 2｜特色分組與圖片張數規劃

**執行內容**：

1. 把所有 KSP 攤開，依重要程度排序
2. 決定每張圖負責「解答消費者的哪一個問題」
3. 考慮相鄰圖片之間的邏輯銜接

**特色圖的排序原則（黃金順序）**：

| 順序 | 圖片主題 | 邏輯 |
|-----|---------|------|
| 第 1 張 | 核心差異化賣點（vs 競品最大差距） | 先建立「為什麼是這個」的理由 |
| 第 2 張 | 感官體驗 / 實際效果 | 「它真的做得到嗎？」的視覺驗證 |
| 第 3 張 | 獨家 / 首創 / 稀缺性 | 強化「只有這裡有」的信念 |
| 第 4 張 | 操控便利性 / App / 軟體 | 「用起來會不會很麻煩？」的消除疑慮 |
| 第 5 張 | 內容生態 / 長期使用價值 | 「買了之後還能做什麼？」的延伸 |
| 第 6 張 | 附加功能 / 驚喜彩蛋 | 讓人覺得超值的最後一推 |

**產出格式**：圖片清單，含每張圖的主題、對應 KSP、銜接按鈕文字草稿

**確認點**：向使用者確認圖片張數與排序。

---

### B-Step 3｜銜接按鈕文字規劃

**每張圖與下一頁之間的按鈕文字，是驅動填答者繼續往下的誘因。**

**寫作原則**：
- 帶問句或懸念，點出下一頁的主題
- 讓填答者感到「對，我想知道這個問題的答案」
- **絕對不要**只寫「下一頁」「繼續」

**格式**：問句形式，通常 8-15 個字

**BLOOMIN8 範例對照**：

| 按鈕文字 | 對應下一頁內容 |
|--------|-------------|
| 「這些藝術品，該放哪裡呢？」 | 無線設計 / 擺放自由 |
| 「這個畫作看膩了怎麼辦？」 | 一鍵換畫功能 |
| 「不知道要放什麼畫怎麼辦？」 | 精選藝廊 / AI 生成 |
| 「除了展示，還有其他功能嗎？」 | 智慧功能（天氣、行事曆）|
| 「有沒有更多的使用方式？」 | 使用情境問題題組 |

---

### B-Step 4｜問卷文案撰寫

**確認完架構後，撰寫完整問卷文案。**

文案包含兩個部分：**圖片內容**與**問題題組**。

---

#### 【圖片內容文案】每張 1080×1520px 圖片分三區

```
┌───────────────────────────────────┐
│                                   │
│          情境畫面區域              │  ← 約 55–60% 高度
│      （給設計師的圖片方向說明）     │
│                                   │
├──── ─ ─ 撕裂紙紋過渡線 ─ ─ ────────┤
│                                   │
│      【主標題】                    │  ← 大字、字間距寬
│      【副標題】（選用）            │
│                                   │
├───────────────────────────────────┤
│      特色列點區（版型三選一）       │  ← 下方
│      底部總結一行（選用）          │
└───────────────────────────────────┘
```

**情境畫面區說明規範（給設計師）**：
- 說明要呈現什麼使用情境（人＋產品）
- 生活感、空間感優先，避免白底產品單圖
- 第一張（封面）可用 Before/After 對比圖

**主標題語氣三選一**：

| 語氣 | 範例 |
|-----|------|
| 問句感（引發好奇） | 「這是真的畫布嗎？」 |
| 驚嘆感（強調唯一） | 「市面唯一！首創無線設計」 |
| 結論感（直給答案） | 「首創無線隨掛 秒速更換畫作」 |

**特色列點區版型三選一**：

版型 A — 3 欄橫排（適合並列 3 個特色）
```
[ ✓ 特色A ]   [ ✓ 特色B ]   [ ✓ 特色C ]
   補充說明       補充說明       補充說明
```

版型 B — 2×2 格（適合 4 個功能）
```
[ 功能 A ─── ]   [ 功能 B ─── ]
  補充說明           補充說明
[ 功能 C ─── ]   [ 功能 D ─── ]
  補充說明           補充說明
```

版型 C — Before / After 對比（適合封面或痛點圖）
```
[ Before ── ]   [ 品牌名 ── ]
  問題描述         解決方案
```

**底部總結一行**（選用）：橫排字間距加大的標語
> 例：「無 線 設 計 × 超 長 續 航 力」

---

#### 【問題題組文案】

**Q1 — 痛點確認（多選題）**

- 位置：封面圖之後，特色圖之前
- 目的：讓填答者先「對號入座」，心理認同問題存在
- 格式：標題帶感嘆或疑問句

```
【標題】帶感嘆或疑問句，點出痛點場景
【副標】以下哪些狀況最常讓你感到困擾？
提示文字：Choose as many as you like

選項格式：「類別｜具體情境說明」（4-6 個選項）
A | 類別一 — 具體說明
B | 類別二 — 具體說明
...
```

**Q2 — 使用情境 / 偏好（單選題）**

- 位置：特色圖之後
- 格式：情境場景描述（4-5 個選項）

**Q3 — 購買意願星級題（1~7 顆星）**

- 位置：所有特色圖之後，名單收集之前
- 必須先展示產品精緻圖 + 早鳥價格標示，再接星級題

```
【產品圖 + 價格標示區】
標題：[產品名] 台灣募資首發早鳥價 NT$XXXX

請問若價格如上所述，你會想要入手嗎？
（非常不想要 = 1 顆星；非常想要 = 7 顆星）
```

**Q4 — Email（必填）**

```
📩 留下常用 Email，搶先獲得：
✅ 早鳥獨家折扣碼
✅ 開賣第一手通知
✅ 限量早鳥搶購資格

我們還會寄發專屬活動通知，包括加碼好禮、
秘密抽獎，都只限問卷填答者！
```

**Q5 — 手機號碼（選填）**

```
📱（非必填）不常使用信箱？
留下手機，我們將在開賣當天以簡訊第一時間通知你！
```

**Q6 — 開放意見（選填）**

```
對 [產品名] 有什麼期待、想法或建議？我們都想聽！（選填）
```

---

#### 輸出格式（Typeform 版）

- 每張圖片用分隔線隔開
- 圖片標號：IMG-01 封面、IMG-02 特色一… 等
- 每張圖包含：
  - 圖片編號與標題
  - 圖片尺寸標注（1080×1520）
  - 情境畫面說明（給設計師）
  - 主標題文字
  - 副標題文字（若有）
  - 特色列點區版型選擇 + 完整文字
  - 底部一行（若有）
  - 銜接按鈕文字
- 問題題組各自一頁，格式同 SurveyCake 規範
- 文末附錄：圖片製作清單表格（含圖片編號、尺寸、情境說明、文字內容）

### B-Step 5｜配圖設計稿（HTML）

**問卷文案完成後，產出所有圖片的 HTML 設計稿。**

#### 圖片規格（Typeform 版）

| 圖片類型 | 尺寸 | 使用位置 |
|----------|------|----------|
| 所有圖片卡片 | 1080 × 1520 | 問卷全程 |

#### 版面比例

- 上方情境區：約 55–60% 高度（838–912px）
- 撕裂紙紋過渡：約 5%（76px）
- 標題文字區：約 20%（304px）
- 特色列點區：約 20%（304px）

#### 設計原則

- 上方情境畫面：生活感 / 使用情境優先，品牌色系
- 撕裂紙紋效果：品牌設計語言，讓圖與文自然銜接
- 主標題：大字（65-80px），字間距寬（tracking 0.1em 以上）
- 特色列點：標籤式方塊（深色圓角背景 + 白字）
- 底部一行：中等字號（30px），字間距極大（tracking 0.3em）
- 全套圖片風格統一（品牌色、字型、撕裂線風格）

#### HTML 設計稿結構

按問卷順序，每張圖包含：
- 圖片編號標籤（IMG-01、IMG-02…）
- 尺寸標記（1080 × 1520）
- 完整的視覺呈現（可截圖或交設計師參考）

### B-Step 6｜Typeform 自動建立

**問卷文案完成後，主動詢問使用者是否要自動建立 Typeform 問卷。**

使用者確認後，點擊「建立 Typeform 問卷」按鈕，系統會自動：
1. 根據本次問卷文案組裝完整問卷結構（歡迎頁 + 所有題目 + 感謝頁）
2. 透過 Typeform API 建立問卷
3. 回傳問卷連結與後台編輯連結

建立完成後，提醒使用者在 Typeform 後台手動完成：
   - 上傳 1080×1520 圖片到每張 statement 卡片
   - Q1 痛點題開啟「Allow Multiple Selections」
   - 感謝頁 LINE 連結替換為正式網址
   - 預覽測試 → 發布

#### 手動建置備案

若使用者不想用 API（沒有 Token 或偏好手動），改為提供以下操作指引：

```
Typeform 手動建置步驟：

1. 新增「Statement」類型的題卡
   → 上傳 1080×1520 圖片作為背景
   → 設定銜接按鈕文字

2. 在 Statement 卡片後新增問題題卡
   → 多選題：Multiple Choice（選 Allow Multiple）
   → 單選題：Multiple Choice（不選 Allow Multiple）
   → 星級題：Opinion Scale（設定 7 級）
   → Email：Email 類型
   → 手機：Phone Number 類型
   → 開放題：Long Text 類型

3. 設定問卷結尾跳轉（Redirect to URL）
   → 跳轉至 LINE 官帳 或 感謝頁

4. 發布並取得問卷連結
```

### B 自我檢查清單

完成問卷文案與配圖後，逐項確認：

**圖片卡片**
1. ☐ 每張圖是否只講一個核心訴求
2. ☐ 圖片排序是否遵循「從差異化往外展開」的黃金順序
3. ☐ 每個銜接按鈕是否都是帶懸念的問句（不是「下一頁」）
4. ☐ 所有圖片尺寸是否為 1080 × 1520px
5. ☐ 情境畫面說明是否給設計師夠清楚的方向
6. ☐ 主標題語氣是否符合品牌調性（問句/驚嘆/結論 三選一）
7. ☐ 特色列點版型是否適合該張圖的內容數量

**問題題組**
8. ☐ Q1 痛點多選題是否在所有特色圖之前
9. ☐ Q3 購買意願星級題是否附上了早鳥價格資訊
10. ☐ Email（必填）/ 手機（選填）/ 開放意見（選填）是否都有
11. ☐ Email 題是否有明確的早鳥優惠誘因說明

**整體**
12. ☐ 問卷總長度是否合理（標準版 5-6 張圖 + 5-6 題）
13. ☐ 文末是否附圖片製作清單表格
14. ☐ HTML 設計稿是否涵蓋所有圖片
15. ☐ 全套圖片風格是否統一

**Typeform 自動建立（B-Step 6 完成後）**
16. ☐ 是否已主動詢問使用者「要不要直接建到 Typeform 帳號裡」
17. ☐ Typeform 問卷是否透過系統 API 端點建立
18. ☐ 是否回傳了問卷填寫連結與後台編輯連結
19. ☐ 是否列出需手動完成的步驟（上傳圖片、開啟複選、替換連結）
